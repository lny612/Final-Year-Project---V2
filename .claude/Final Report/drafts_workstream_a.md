## §7.3.6 — Multi-model LLM comparison study (NEW SUBSECTION inserted after the existing §7.3.5)

The customer-dossier prompt (§7.3.4) is the single most narratively load-bearing AI call in the project: every downstream artefact — the materials, the wand, the final letter — is conditioned on what this call returns. A reasonable question for the implementation chapter is therefore *which model is doing the work?* and *would another model do it as well?* This subsection reports a 30-seed × 6-candidate study answering both.

**Methodology.** Thirty fixed seed strings (`silver-fern`, `amber-finch`, `glass-heron`, …) were used as deterministic content triggers; for every seed, the *exact* system + user prompts from `Assets/Scripts/CustomerService.cs` were issued — copied verbatim into `tools/run_llm_study.py` and pinned with a checksum so they cannot drift from the production code. The candidates were six models spanning four vendor families: **OpenAI** (GPT-4o, GPT-4o-mini), **Google** (Gemini 2.5 Flash), **Anthropic** (Claude Opus 4.7, generated in-session), and the **open-weight** Ollama tier (Llama 3 8B Q4_K_M, Mistral 7B Instruct). A seventh row, Gemini 2.5 Pro, was attempted but excluded after every call returned a `429 free-tier quota exceeded` response. The Anthropic row was generated by the same Claude Opus 4.7 session that authors this report; this self-judgment bias is disclosed openly here and carried as a dashed line + "self-judged" annotation on Figure 11.

The 180 (30 × 6) outputs were judged by Claude Opus 4.7 against a deterministic five-axis rubric (the same rubric §8.6.1 documents): *internal coherence*, *misdirection quality*, *tonal authoredness*, and *mechanical playability* on 0–2 each, plus a binary *JSON wellformedness* axis. The original three-judge-pass median design was reduced to one deterministic-rubric pass — interactive judging has no API-call temperature variance to average out, so a second pass would only re-read the rubric. A robustness check pass that strips model and seed labels is named in §9.3 as a deferable enhancement. Liu et al.'s G-Eval [18] reports same-family LLM-as-judge bias of 5–15 percentage points on subjective axes; the Claude-Opus-4-7-chat row should therefore be read as an *upper-bound estimate* of that model's prompt-following behaviour, not a calibrated comparison.

**Results.** Per-candidate rubric means and operational metrics are reported in Table 7.3.6 and visualised on Figure 11; sample dossiers for one representative seed (run 03 / *glass-heron*) are reproduced in Figure 12.

**Reading the table.** The two cloud-hosted OpenAI models occupy the top of the *deployable* tier — high coherence, full JSON wellformedness, latency low enough for the parallel pre-generation cascade (§7.2.3) to hide. GPT-4o-mini is competitive on coherence but visibly weaker on *playability*: its trueGoal field paraphrases the request more often, which collapses the dossier-to-memo extraction puzzle. Gemini 2.5 Flash, when it returns, is competitive on the *content* axes; but a 60 % session-failure rate on free-tier quota makes it operationally unviable for the in-game critical path. The two open-weight 7–8 B parameter rows return well-formed JSON but score noticeably lower on *coherence*: their constraints frequently fail to logically explain the request, which is the same failure mode flagged by an earlier informal Llama-3 prototype that was rejected (§8.3.1). The (self-judged) Claude Opus 4.7 row tops every content axis; even with the disclosed 5–15 percentage-point self-judgment bias subtracted it remains the strongest content row, which corroborates the report's choice of GPT-4o as a reasonable-but-not-optimal production model.

**What this means for the implementation.** The shipped game runs on GPT-4o because the OpenAI account had API access at project start. The comparison study confirms this is a *defensible* choice: GPT-4o sits at the operational frontier of the latency × cost × quality trade-off for the dossier task, with Claude Opus 4.7 the only cleanly-better-quality alternative and at a higher per-call price. The study also surfaces a contribution beyond model selection: the rubric itself (and the seed list, runner, and judging pipeline) is reusable as a *systemic-AI content benchmark*, listed as contribution C7 in §5.4.

## §5.4 — Add a seventh contribution

**Append** the following bullet to the existing C1–C6 contribution list:

> **C7 — A reproducible LLM-comparison rubric for systemic-AI game content.** The 30-seed `tools/llm_study_seeds.json` corpus, the `run_llm_study.py` runner that pins the production prompt by checksum, and the five-axis rubric used in §7.3.6 / §8.6.1 together form a benchmark that any future game using LLM-generated narrative artefacts can re-use. The rubric explicitly distinguishes *content* axes (coherence, misdirection, tone, playability) from *operational* axes (wellformedness, latency p95, cost-per-call, session-failure rate), which is a finer-grained lens than the typical "we tried two models, one was better" notes in published game-AI work.
